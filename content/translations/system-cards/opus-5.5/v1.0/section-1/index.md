Claude Opus 5.5 是 Anthropic 推出的一款新的大语言模型（large language model），已以全面开放的方式发布，并在三个高风险的两用领域部署了安全防护措施：生物学（第 2.2 节）、网络安全（第 3.2 节），以及支持前沿 AI 开发的一小部分能力（第 1.5 节）。在本系统卡（System Card）中，我们报告了在七个领域开展的一系列部署前评估：负责任扩展政策（Responsible Scaling Policy）评估、网络安全、安全防护与无害性、智能体安全、对齐（alignment）、模型福祉（model welfare）以及能力。

### 1.1 训练数据与过程

Claude Opus 5.5 的训练数据是一个专有组合，包括来自互联网的公开信息、公开和非公开数据集、反馈或错误报告中包含的用户数据或用户已明确允许用于训练的用户数据，以及其他来源，例如由其他模型生成的合成数据。在训练过程中，我们使用了多种数据清洗和过滤方法，包括去重和分类。我们使用一款名为 ClaudeBot 的通用网络爬虫从公共网站获取训练数据。该爬虫遵循行业标准的最佳实践，尊重网站运营者设置的“robots.txt”指令，这些指令表明他们是否允许爬取其网站内容。我们不会访问受密码保护的页面，也不会访问需要登录或 CAPTCHA 验证的页面。我们会对所使用的训练数据进行尽职调查。该爬虫以透明方式运行；网站运营者可以轻松识别它何时爬取了其网页，并向我们表明他们的偏好。

在预训练过程之后，Claude Opus 5.5 经历了严格的后训练和微调，目的是使其成为一个行为符合 [Claude 宪法](https://www.anthropic.com/constitution)（Claude’s constitution）中所述价值观的助手。Claude 支持多种语言，通常使用与用户输入相同的语言进行回复。输出质量因语言而异。该模型仅输出文本。

Claude Opus 5.5 的知识截止日期为 2026 年 6 月。

### 1.2 众包工作者

Anthropic 与数据工作平台合作，招募工作者通过偏好选择、安全评估和对抗性测试来帮助改进我们的模型。Anthropic 只与这样的平台合作：它们认同我们为工作者提供公平且合乎道德的报酬这一理念，并承诺无论身处何地都践行安全的工作场所规范，遵循我们在采购合同中详细规定的众包工作者身心健康标准。

### 1.3 使用政策与支持

Anthropic 的[使用政策](https://www.anthropic.com/legal/aup)（Usage Policy）详细列出了我们模型的禁止用途，以及我们对高风险场景和其他特定场景中的使用所提出的要求。

对于受适用监管制度约束的模型，我们已在[前沿合规框架](https://trust.anthropic.com/resources?s=zgt6rgfecy1eo7vicr064b&name=anthropic-frontier-compliance-framework)（Frontier Compliance Framework，FCF）中正式规定了我们如何履行此类法规下的义务。FCF 记录了我们当前针对各主要风险类别开展系统性风险评估与缓解的技术和组织规程。FCF 是我们针对适用监管制度的合规框架，这些制度包括加利福尼亚州的《前沿人工智能透明度法案》（Transparency in Frontier AI Act，SB 53）以及《欧盟人工智能法案》（EU AI Act）的通用人工智能行为准则（General-Purpose AI Code of Practice）。

Anthropic Ireland, Limited 是 Anthropic 通用 AI 模型在欧洲经济区（European Economic Area）的提供方。

### 1.4 模型评估

在训练过程中的不同时间点，我们会获取 Claude Opus 5.5 的不同“快照”。除非某一节另有说明，本系统卡中的评估均在 Claude Opus 5.5 的最终快照上运行。部分章节则使用了较早的或替代的快照，或在禁用生产环境安全防护措施的情况下运行模型，以使结果反映底层模型而非已部署的系统。每一节都会说明其配置。

### 1.5 安全防护措施

我们为 Claude Opus 5.5 的全面开放使用所采用的安全防护措施如下：

- 针对化学与生物（CB）风险，我们部署了与 Claude Fable 5 和 Claude Fable 5.1 部署中所用相同的研究生物学分类器。与 Claude Opus 5 及能力较弱的模型上所用的 CB 滥用分类器相比，这些分类器覆盖的主题范围更广。被该分类器拦截的请求将回退（fallback）至 Claude Opus 5。我们使用这些分类器的理由将在第 2.2.5 节中讨论。
- 针对网络安全滥用，我们部署了拦截主题范围与 Claude Opus 5 上的分类器相似、但鲁棒性更高的分类器。被这些分类器拦截的请求将回退至 Opus 4.8。我们将在第 3.2 节中进一步介绍这些分类器。
- 正如我们[8 月风险报告](https://anthropic.com/aug-2026-risk-report)（Risk Report）第 3 节所讨论的，我们担忧加快模型开发整体步伐所带来的风险，以及递归自我改进（recursive self-improvement，RSI）可能带来的风险。我们已在 Claude Opus 5.5 上针对一小部分与开发前沿大语言模型（LLM）相关的能力部署了安全防护措施，例如在某些 ML 加速器上进行内核开发，这与我们在 Claude Fable 5.1 上的相应安全防护措施类似。这些措施不会影响绝大多数传统的 AI 或 ML 开发、研究或一般编程工作。被这些分类器拦截的请求将回退至 Claude Opus 5。
{{< s1-page 12 >}}
- 我们针对常规武器和高当量炸药开发的拦截分类器，其表现与 Claude Fable 5.1 等以往模型相似，且没有回退模型。
- 我们用于防止对我们模型进行蒸馏（例如试图提取模型的隐藏推理）的分类器，将在 Claude Opus 5.5 上直接拦截，没有回退模型。

上述回退行为适用于我们的第一方产品，以及在我们的 API 上选择启用此类回退的开发者；通过其他平台和提供商使用我们模型的流量可能会出现不同的行为。我们所有的拦截类安全防护措施均采用透明拦截的方式运行，不会暗中更改模型的回复。

### 1.6 外部测试

Claude Opus 5.5 的大部分评估是在 Anthropic 内部运行的。作为 FCF 的一部分，我们还邀请外部评估方对该模型的不同迭代版本进行测试。他们的意见有助于我们对系统性风险领域作出风险判定，也有助于我们的发布决策。我们感谢所有外部测试方对 Claude Opus 5.5 开展评估并与我们分享结果。他们的具体贡献在本系统卡的相关章节中介绍。
